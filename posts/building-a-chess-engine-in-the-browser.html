Building a 60 FPS Chess Engine in the Browser

How we built an interactive, 100% static Chess AI featuring 64-bit Zobrist Transposition Tables, Micro-NNUE neural network evaluation, and thread isolation with Web Workers.

Building a chess engine that runs entirely in the browser without any backend server presents unique challenges: JavaScript runs in a single-threaded event loop, and executing deep minimax tree searches on the main thread immediately freezes the browser UI, causing dropped frames and laggy piece dragging.

In this writeup, we explore the key techniques used to build Chess AI, keeping the user interface at a buttery 60 FPS while evaluating thousands of positions in parallel.

1. Multi-Threaded Architecture with Web Workers

To decouple heavy computation from the UI, the engine offloads all search operations to a dedicated Web Worker (worker.js). The main thread strictly handles chessboard rendering, animations, and user input: 

// Main thread dispatches search request without blocking UI
engineWorker.postMessage({
  type: 'SEARCH',
  fen: game.fen(),
  depth: 4,
  evalMode: 'nnue',
  isWhite: false
});

// Worker streams real-time search telemetry back
engineWorker.onmessage = function(e) {
  if (e.data.type === 'BEST_MOVE') {
    game.ugly_move(e.data.bestMove);
    board.position(game.fen());
  }
};

2. 64-Bit Zobrist Transposition Tables

Different move sequences often lead to identical board positions (transpositions). Rather than re-evaluating subtrees from scratch, we use Zobrist Hashing with pre-allocated Typed Arrays (BigUint64Array and Int32Array) to maintain an in-memory hash table of 524,288 entries (~16 MB):

$$\text{Hash}(S) = \bigoplus_{sq=0}^{63} \text{ZobristPieces}[\text{piece}(sq), sq] \oplus \text{SideToMove}$$

When searching a position, the engine probes the table. If a previous search evaluated this exact state at an equal or greater depth, it produces an immediate \(O(1)\) cutoff:

  • Exact Cutoff: Stored score reflects true minimax value within bounds.
  • Lowerbound Cutoff: Stored score caused a beta-cutoff (\(\text{score} \ge \beta\)).
  • Upperbound Cutoff: Stored score failed low (\(\text{score} \le \alpha\)).

3. Micro-NNUE: Neural Network Evaluation

In addition to classical Piece-Square Tables (PST), the engine implements Micro-NNUE—a quantized \(768 \to 32 \to 32 \to 1\) neural network evaluated with dual accumulators and Clipped-ReLU integer arithmetic:

$$\text{CReLU}(x) = \min(\max(0, x), 127)$$

The dual-accumulator architecture calculates features simultaneously from White's and Black's perspective, ensuring that symmetrical positions return an exact score of \(0.00\).
